# prompts — 回答者と検験者の system prompt

| ファイル | 役割 | 呼び出し |
| --- | --- | --- |
| `responder.ja.md` | 回答者。手順と判断標準に従って問いを出す | 段階ごとに 1 回／利用者の送信 |
| `verifier.ja.md` | 検験者。回答者の出力を検査し JSON で判定 | 回答者の出力ごとに 1 回 |

英語・中国語版は書稿の翻訳に合わせて `.en.md`、`.zh.md` を追加する。

## 占位符

アプリ（`src/pages/api/chat.ts`）が送信前に文字列置換する。未置換の `{{…}}` が残っていたら送信せずエラーにする。

| 占位符 | 内容 | responder | verifier |
| --- | --- | --- | --- |
| `{{STEP}}` | 現在の段階。`procedure.ja.md` の見出し（「① 問題と理想の最終結果（IFR）」等）をそのまま | 必須 | 必須 |
| `{{CRITERIA}}` | `criteria.ja.md` の該当段階の節（標準提問・通過・昇格・拒否）と「共通の原則」「拒否の規則」 | 必須 | — |
| `{{USER_INPUT}}` | 利用者がこれまでに書いた欄を「欄名: 内容」で改行連結。空欄は「（未記入）」 | 必須 | 必須 |
| `{{CONFIDENCE}}` | 段階④の確信度（0〜100）。④以外は「未入力」 | 必須 | — |
| `{{ALLOWED_CHAPTERS}}` | `principles.ja.md` の「本の該当章」列に現れる章名の一覧（改行区切り） | — | 必須 |
| `{{RESPONDER_OUTPUT}}` | 検査対象の回答者出力 | — | 必須 |

ヒント昇格は `{{USER_INPUT}}` の末尾に「ヒント要求: レベル n」の行を足して伝える。

## 版本番号の規則

- 各ファイルの 1 行目は `<!-- PROMPT_VERSION: n -->`。`n` は正の整数。
- 文言を 1 文字でも変えたら `n` を 1 増やす。設計メモ（HTML コメント）だけの変更は増やさない。
- responder と verifier の版は独立。アプリは呼び出しごとに両方の版を事件ログ（`ai_called.prompt_version`）に記録する。
- 旧版は Git 履歴で参照する。ファイルを複製して残さない。
- 版を上げたら `docs/triz-design.md` に「何を・なぜ変えたか」を 1 行追記する（発表時の演進説明に使う）。
